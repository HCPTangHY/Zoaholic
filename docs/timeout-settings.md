# 超时与心跳设置

系统设置和渠道编辑器均提供“超时与心跳”面板。子渠道可通过“完整编辑”设置自身规则。面板不自动修改已有配置；修改后需要保存。

## 三项设置

| 设置 | 配置字段 | 程序预设 | 关闭方式 |
| --- | --- | --- | --- |
| 首包等待上限 | `stream_header_timeout`，兼容 `header_timeout` | 60 秒 | 选择关闭，保存为 `0` |
| 网络读取超时 | `model_timeout` | 600 秒 | 不支持关闭，必须大于 `0` |
| SSE 心跳间隔 | `keepalive_interval` | 15 秒 | 选择关闭，保存为 `0` |

默认值可以由服务环境变量 `STREAM_HEADER_TIMEOUT`、`TIMEOUT`、`KEEPALIVE_INTERVAL` 覆盖。管理接口 `/v1/api_config` 在顶层返回 `timeout_defaults`，面板据此显示服务默认值。旧后端没有这一项时，面板会明确标记程序预设值仅供参考。

`model_timeout` 传给上游 HTTP 客户端，不是整个生成过程和全部重试共用的总时限。首包保护启用时，网关不会仅因心跳周期到达就在尚未确认上游首包的情况下发送 `200`。首包等待阈值还受网络超时约束；上游活动会影响等待计时，不能把它理解为整次请求的固定截止时间。心跳间隔不小于有效网络超时时，不启用心跳。

## 默认值和模型规则

每项可选择沿用配置或指定秒数。首包等待和心跳还可选择关闭。展开“按模型设置”后，可以添加模型名或匹配片段，分别指定秒数或关闭。

- 模型规则不是通配表达式，不需要添加 `*`。
- 沿用后端现有匹配方式：优先查找精确键，再依配置顺序查找包含片段，最后使用 `default`。建议模型名使用小写。
- 渠道自己的默认值优先于全局的模型规则。删除一条模型规则，不一定恢复全局继承；它可能改用渠道默认值。
- 渠道整项未配置或为空字典时，后端使用全局规则先匹配请求模型名。有渠道规则但未匹配时，则按请求名、上游名和全局上游名依次查找。请求别名和上游名称不同时，需检查实际匹配结果。
- 子渠道按字段继承主渠道；模型字典是整项覆盖，不是逐条合并。显式设置与主渠道相同的值仍保留为自身配置。

“查看模型生效值”可输入请求模型名和可选的上游模型名，显示草稿中的匹配值、来源和规则。它不发送模型请求，也不修改配置。预览不涵盖内部 Key 路由和测试时的临时超时覆盖。

## 慢首包模型示例

若需要让 `gemini-4-carbon` 长时间等待首包，而其他模型继续使用保护：

1. 打开实际使用的渠道编辑器，找到“超时与心跳”。
2. 在“首包等待上限”的模型规则中添加 `gemini-4-carbon`。
3. 将该规则设为“关闭首包限制”，保留其他默认值和模型规则。
4. 检查网络读取超时和心跳间隔，再使用生效值预览确认匹配来源。
5. 保存配置。

对应配置示例：

```yaml
preferences:
  stream_header_timeout:
    default: 60
    gemini-4-carbon: 0
  model_timeout: 900
  keepalive_interval: 20
```

请合并到已有偏好配置，不要覆盖其他字段。面板不会自动添加这个例外，也不会自动更改生产参数。

关闭首包保护且启用心跳后，网关可能提前提交 `200` 流式响应。后续上游错误可能只能以流内错误返回，不能再按发送响应前的方式更换 HTTP 状态码。客户端、反向代理和 CDN 仍可能有独立超时，心跳不能保证取消这些限制。

## 保存和兼容性

- 支持原有数值和模型字典；打开面板不会把继承值写成显式默认值。
- 首包字段编辑后使用标准名 `stream_header_timeout`，并移除本层旧别名，避免旧值重新生效。
- 子渠道和主渠道同时存在标准名与别名时，遵守后端浅合并后的标准名优先规则，面板提供提示。
- 全局恢复继承通过 `null` 显式删除字段；渠道保存时直接移除自身字段。
- 空白、非有限数字、无效模型规则、重复模型名会阻止保存；网络读取超时必须为正数，心跳为整数秒。
- 管理接口也进行相同类型的校验。已有负数首包或心跳配置保留旧的关闭语义，新关闭操作统一保存为 `0`。
- 本次界面调整不改变后端首包保护或重试策略。

# 安全边界与初始化要求

## 初始化是所有 API 的前置条件

必须完成管理员账号初始化后，普通 API Key、管理员 API Key 和管理员 JWT 才能访问受保护接口。仅配置 `api.yaml`、`ADMIN_API_KEY` 或 `JWT_SECRET`，不能代替管理员账号初始化。HTTP 模型接口、管理接口及 Responses WebSocket 使用同一要求。

- **首次安装**：没有配置，也没有管理员账号时，通过 `/setup` 创建管理员。
- **已有配置、没有管理员账号**：在 `/setup` 提供配置中现有的管理员 API Key，验证通过后补建管理员。普通 User Key 和 JWT 不能用作这一恢复凭据。恢复授权只作用于初始化请求，不开放其他 API。
- **已有管理员、配置缺失**：提供原管理员账号密码验证身份后恢复配置，不能匿名覆盖原管理员账号。
- **配置和管理员都存在**：拒绝重复初始化。
- **数据库关闭**：无法持久化管理员账号，因此不开放受保护 API。需启用数据库并完成初始化。

初始化状态未就绪时返回 `503`。正常就绪请求读取内存状态，不对每次模型调用查询数据库。未就绪的进程可重新检查其他进程完成的初始化结果。外部删除管理员记录或修改密钥后，运行中的进程不保证立即感知，需要重启或明确刷新；此检查不是实时会话撤销机制。

## JWT 签名密钥

不再使用固定开发密钥，也不使用每个进程独立的随机回退密钥。没有可信密钥时拒绝签发或验证 JWT。

优先使用明确配置的 `JWT_SECRET`；否则使用数据库持久化的管理员签名密钥。旧管理员记录缺少密钥时，启动流程使用条件更新补齐随机密钥，并读取数据库中的最终值，避免多进程生成不同密钥。合法的已有密钥不会因这次修复被轮换。

JWT 验证仅接受 HS256 和有限、尚未过期的数值到期时间。初始化未完成时，即使具备合法签名，JWT 也不能开放业务接口。

正常重启复用原签名密钥，有效期内的 JWT 继续可用。需要撤销全部 JWT 时，主动轮换签名密钥并让所有进程加载新密钥。此操作不会撤销静态管理员 API Key，泄露的 API Key 必须单独更换。

## 静态文件

`assets` 和 `icons` 在 SPA 兜底路由之前注册。其他静态文件请求校验解码后的路径和解析后的真实目录归属，拒绝父目录片段、异常路径及指向静态目录外的符号链接。越界访问返回 `404`，不再返回文件或以 SPA 页面掩盖拒绝结果。

保留静态资源的长期 `immutable` 缓存和 ETag 条件请求；首页及 SPA 页面使用 `no-store`，错误响应不加长期缓存。

文件读取范围以服务进程权限为上限。反向代理对某些路径的拒绝不能代替后端检查：用户提交的远程文件 URL 可能让服务从内部请求自身。

## 用户提供的文件与图片 URL

共享文件下载路径仅允许 HTTP(S) 公网目的地址：

- 在实际 TCP 连接前异步解析 DNS，并检查全部地址；存在私网或特殊用途地址时拒绝整次连接。
- 仅向已验证的数字 IP 建立连接，原域名保留用于 HTTP Host、TLS SNI 和证书验证。
- 不使用环境代理绕过地址检查，开启 TLS 证书校验。
- 基于公开的 HTTPX Transport 接口接入 httpcore，显式声明 httpcore 依赖；请求、响应流读取和关闭时保持 HTTPX 异常类型约定。
- 不自动跟随重定向；最多处理 5 次，每跳重新验证目标，连接层继续校验 DNS。
- 不向客户端返回签名 URL、内部地址和底层网络错误细节。
- 单次远程文件下载不超过 50 MiB，同时检查声明长度和实际流量。
- 请求不压缩的 HTTP 响应，拒绝服务端仍发送的 HTTP 内容压缩，避免解压炸弹。PDF、ZIP 等文件自身的压缩格式不受此条限制。
- 保留 `data:` URI 和原始 Base64 支持。

这是有意的兼容性变化：指向本机、内网、云元数据服务或自签名 HTTPS 的文件链接将被拒绝。该限制作用于用户提供的文件下载，不改变管理员配置的模型上游连接。

## 管理员插件权限

**保留管理员安装并执行任意 Python 插件的能力。**这不是沙箱，管理员凭据应按服务进程级高权限凭据保管。插件加载失败也不能撤销模块已经执行的代码。

上传及解压路径必须位于插件目录内。客户端文件名不能包含目录路径；拒绝目标符号链接、ZIP 路径穿越、符号链接、特殊文件、重复成员及加密成员。

限制如下：

| 项目 | 上限 |
| --- | --- |
| 上传文件 | 16 MiB |
| ZIP 解压总量 | 64 MiB |
| ZIP 成员数 | 1024 |

上传在私有暂存目录中完成校验后安装。加载失败时恢复原有磁盘文件，不承诺恢复任意插件代码产生的运行时副作用。

## 部署与事件处置

代码修复不代表凭据已恢复安全。部署后应使用无敏感标记文件验证路径读取被拒绝，并核对文件抓取的私网限制。不要为验收读取真实配置或上传执行命令的插件。

如有历史利用迹象，应先保存访问日志、插件变更和配置记录，再评估管理员 Key、JWT 签名密钥、上游 API Key 及 OAuth 凭据的轮换范围。凭据轮换和部署需要单独执行，不能把源代码测试通过当作生产已修复。

建议服务使用独立的低权限系统用户运行。保留插件自由度并不意味着需要让插件拥有 root 权限。
